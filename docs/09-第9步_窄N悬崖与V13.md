## 真正的瓶颈：N<16 掉进单核标量路径

`BmmmsCube::TryRun` 里有一行：

```cpp
const int32_t maxN = (boundedN / BLOCK) * BLOCK;
if (maxN < BLOCK) {
    return false;   // N < 16 -> bmmms_starter_kernel
}
```

Cube 基本块宽度是 16 的倍数，所以 N<16 全部回退到单核逐元素的 `bmmms_starter_kernel`。真机实测标量路径速率为 **37.6 ns/元素**，与数据量严格线性。

910B2 实测（msprof `BasicInfo / Task Duration(us)`，预热 3 次）：

| 形状 | N | 工作量 | V08D | V12 | 加速 |
|---|---:|---:|---:|---:|---:|
| `1_8192_8_32` | 8 | 2097152 | 72516.8 μs | **54.78 μs** | **1324×** |
| `1_2048_15_32` | 15 | 983040 | 33790.4 μs | **31.40 μs** | **1076×** |
| `1_8192_1_32` | 1 | 262144 | 9858.9 μs | **58.02 μs** | 170× |
| `1_4096_1_64` | 1 | 262144 | 9817.8 μs | **72.68 μs** | 135× |
| `1_1024_1_256` | 1 | 262144 | 9762.0 μs | **225.32 μs** | 43× |
| `1_512_1_32` | 1 | 16384 | 618.4 μs | **31.50 μs** | 19.6× |
| `1_8192_16_32` | 16 | 4194304 | 112.12 μs | 110.96 μs | 对照，无变化 |
| `1_1024_16_256` | 16 | 4194304 | 34.72 μs | 35.26 μs | 对照，无变化 |

N=16 比 N=1 多 16 倍工作量却快 88 倍，悬崖位置与代码完全吻合。N≥16 的两个对照点没有变化，说明改动是隔离的。

按 37.6 ns/元素反推官网各点的标量工作量：点 2 约 542、点 3 约 8830、点 13 约 1705、点 14 约 4788。这些都落在标量路径的特征区间内。

## V12 的做法：算转置积

直接让 Cube 处理 N<16 行不通。C 块是 `[validM, N]` 紧凑布局，行距 N 个 float；N=1 时行距 4 字节，而 `WholeReduceMax` 的步长按 32 字节编码，表达不了。先试 `enSequentialWrite=false` 想拿到固定 baseN 行距，narrow 套件直接给出错误结果（−10.16 vs −1.39），说明该标志并不改变行距语义。

改为计算**转置积** C^T = B^T·A^T，形状 `[N, M]`：

- 「沿 N 取最大」变成**整行之间的逐元素 `Max`**，行是连续向量，没有步长问题。
- 「沿 M 求和」变成一次 `ReduceSum`。

操作数互换、两个转置标志取反即可，不需要任何数据搬移：

| 原始 | A' = x2 视作 [N,K] | B' = x1 视作 [K,M] |
|---|---|---|
| `tb=false`（x2 存 [K,N]） | `TransA' = true` | |
| `tb=true`（x2 存 [N,K]） | `TransA' = false` | |
| `ta=false`（x1 存 [M,K]） | | `TransB' = true` |
| `ta=true`（x1 存 [K,M]） | | `TransB' = false` |

即 `TransA' = !tb`，`TransB' = !ta`。

### 尾块：不能重叠，要补零

原方向上尾块可以回退重叠，因为重复读列不改变最大值。转置后沿 M 分块，**M 方向是求和方向，重叠会重复计数**。

但尾块的行距有歧义：满宽块按 `baseN` 寻址正确，尾块按自身宽度寻址得到 NaN，按 `baseN` 寻址又少算（`1_17_15_72` 得 78.694，应为 80.283，差值正好是一行的最大值）。

最终做法是**消除尾块**：最后一块回退到 `m0 = M - width` 保证满宽，行距唯一确定为 `width`；归约前把 `acc` 前 `skip = width - fresh` 个元素 `Duplicate` 置零，重叠列因此不计入求和。配套要求 `width <= M`，所以 `M < 16` 暂不走这条路径（保持 V08D 行为）。

## V13 = V12 + 小向量路径

点 2 的工作量约 542，低于 `B*M*N*K > 4096` 的门槛，仍走标量（542 × 37.6 ns = 20.4 μs，与官网 20.38 μs 吻合）。V09C 的 `bmmms_small_vector_kernel`（条件 `M*N <= 32 && B*M*N*K <= 65536`）正好覆盖这个区间，且当时已通过 29/29 回归，直接并入。

V13 的分支顺序：

1. `M==1 && N==1` → `bmmms_dot_kernel`（向量点积）
2. `M*N<=32 && B*M*N*K<=65536` → `bmmms_small_vector_kernel`
3. `N<16 && M>=16 && work>4096` → `TryRunNarrow`（转置 Cube）
4. `work>4096` → `TryRun`（原 Cube 路径，未改动）
5. 其余 → `bmmms_starter_kernel`

每次调用仍只启动一个计算 kernel，分支全部基于一般形状条件，不针对测试点编号。

## 晋级目标与差距

第 32 名 Astra-max 60.33 分，第 33 名 60.30，门槛约 **60.3**。公式 `100/(1+log₁.₅(t/T))` 下，各点均达最优的 1.3 倍对应 60.7 分。

各情景总分测算：

| 情景 | 总分 |
|---|---:|
| 当前 V08D | 18.54 |
| 点 2/3 修到 1.4× 最优 | 24.40 |
| 再加点 13/14 也是窄 N | 29.80 |
| 再加大矩阵快 3 倍 | 34.86 |
| 全部 1.5× 最优 | 50.00 |
| 全部 1.3× 最优 | 60.71 |

**窄 N 修复是单项最大收益，但不足以晋级。** 大矩阵分支（点 8–12，当前慢 4.7–11 倍）必须同步优化，下一步是 TILE_M/TILE_N 的单变量扫描，脚本见 `learning/make_tile_variants.py`。
