V36 将极小输出的长点积交给 Vector 分块计算，在本次同卡、同输入对照中达到约 21～26 倍提速。大矩阵继续采用 Cube 与 Vector 协同计算。

本轮可提交文件是 `CURRENT_SUBMISSION.txt`，版本标记为 `V36_TINY_OUTPUT_VECTOR`。官网分数和前 32 名资格尚待这次提交确认；目标仍按你要求的 60 分以上推进。

**算子在算什么**

每个 query token 与全部 document token 做点积，挑出其中最大的相似度，再把各个 query token 的最大相似度加起来。`B` 是批次数，`M/N` 是两边 token 数，`K` 是每个 token 的向量长度。

`y[b] = sum_m(max_n(sum_k(x1[b,m,k] * x2[b,k,n])))`

四种转置属性只决定输入怎样存储，不改变这条计算公式。

**代码怎样实现**

- 单个点积使用 Vector：搬入数据，转为 FP32，逐元素相乘并归约。
- 输出元素数不超过 4 的矩阵，沿 K 每次处理至多 4096 个元素。所有 K 分块都累加完成后，先沿 N 取最大值，再沿 M 求和。不同 batch 分给不同核心。
- 其他小矩阵在 UB 中复用数据，减少反复读取和逐点同步。
- 大矩阵由 Cube 计算相似度块，Vector 计算行最大值；两块交替缓冲让搬运与计算协同进行。行方向任务不足时，再沿 N 分片。不同 N 分片先合并行最大值，然后才能沿 M 求和。
- 长 K 的部分非对齐存储在同一个核函数内完成整理。Host 只处理形状、布局、分块参数及临时空间；真实输入值的计算全部在 NPU 上完成。每次算子调用只启动一个计算核函数。
