## 这次改了什么

题目先计算两个矩阵相乘的结果，再取每行最大值，最后把这些最大值相加。

7B 用 Cube 单元做矩阵乘法，但取最大值时还在逐个读取全局内存中的结果。V08D 把乘法结果放在片上 UB 缓存，用 Vector 单元批量求每行最大值，并在 UB 中合并不同列块的最大值。各核只把部分求和结果写到全局内存，最后由一个核汇总。

当输出矩阵只有一个元素，即 `M=N=1` 时，问题等价于两个向量的点积。V08D 使用向量类型转换、乘法和求和，替代逐个解码输入并累加。

对于 N 能被列块宽度整除的矩阵，Matmul 在一次会话中连续处理多个列块。其余形状保留覆盖最后一块的处理方式。每次调用仍只启动一个计算 kernel，输入相关运算全部在 NPU 上完成。

## 真机验证范围

设备为租用的 Ascend 910B2，24 个 Cube 核；CANN 9.0.0，编译目标 `dav-2201`。

V08D 已通过以下自建测试组：

| 测试组 | 通过数量 | 覆盖内容 |
| --- | ---: | --- |
| 回归 | 23/23 | FP16、BF16、4 种转置组合、尾块、负数、K=8192、M=8192、B=64 |
| 连续列块 | 18/18 | 多个 N 块、转置、全负结果、N=8192 |
| 点积 | 16/16 | K=32/40/256/4096/8192、批量、BF16、正负抵消 |
| 性能对照样例 | 4/4 | 小矩阵、大矩阵、批量转置 BF16 |

参考结果使用实际存储的 FP16/BF16 数值，在 CPU 上按 FP64 做矩阵乘法、最大值和求和，再转成 FP32。比较条件是 `rtol=1e-4, atol=1e-4`，同时检查输出长度及有限值。CPU 参考代码只存在于测试工具中，不属于提交的 kernel。

61 项测试运行中包含回归重复。它们用于验证新实现，官网 15 个测试点的通过情况和得分需由本次正式提交确认。

## 如何理解计时

使用 `msprof op` 的 `BasicInfo / Task Duration(us)` 测量芯片执行时间，每项采集前预热 3 次。测试程序另有 `host_inclusive_us`，它包含主机端申请内存、生成 tiling 等开销，不用于下表。

同一台卡、相同自建输入，本次采集到的时间如下：

| 自建样例，B=1、FP16 | 7B | V08D | 加速 |
| --- | ---: | ---: | ---: |
| M=N=1，K=4096 | 167.28 μs | 3.40 μs | 49.2 倍 |
| M=N=1024，K=256 | 2091.02 μs | 57.64 μs | 36.3 倍 |
| M=N=2048，K=128 | 4172.62 μs | 163.86 μs | 25.5 倍 |

每个版本、每个样例表中对应一次 profiler 采集，数值反映本次测量。官网硬件和输入不同，实际得分以官网为准。
