# 第 1 步：首次提交与申请算力

报名已经完成。当前任务是提交第一版实际计算代码，取得评测记录，再由队长申请算力。

## 先理解这场比赛

你需要交付一个程序：给定两组数字，算出题目要求的分数，并在昇腾 NPU 上尽快完成。

可以把 query 理解为一次搜索，把 document 理解为一篇候选文档。query 和 document 里的每个词都有一串数字作为特征。程序要做三件事：

1. 用点积计算词与词之间的相似度，形成一张表。
2. 对 query 的每个词，从这一行里挑出最大的相似度。
3. 把挑出的最大值相加，得到这篇文档的分数。

例如相似度表是：

| | 文档词 1 | 文档词 2 | 文档词 3 | 这一行的最大值 |
| --- | --- | --- | --- | --- |
| 查询词 1 | 2 | -1 | 3 | 3 |
| 查询词 2 | -4 | -2 | -5 | -2 |

输出就是 `3 + (-2) = 1`。第二行的最大值必须是 -2。

## 现在只需要记住的词

| 名称 | 当前需要理解的意思 |
| --- | --- |
| 算子 | 完成上述三步的小程序 |
| NPU | 执行计算的昇腾芯片 |
| Ascend C | 写这个芯片上的计算程序所用的语言 |
| Host | 管理形状、参数和程序启动的 CPU 端 |
| kernel | 真正在 NPU 上执行计算的函数 |
| 评测点 / case | 主办方用来检查正确性和速度的一组输入 |
| FP16 / BF16 | 两种输入数字的存储方式，程序都要正确读取 |

比赛的最终目标是 15 个测试点全部通过精度检查，并取得尽可能好的速度。本轮的完成标志是：**产生一条真实提交记录，并用这条记录发起算力申请。**

## 本轮实现与验证说明

`solution/kernel.asc` 的 Host 部分只读张量元信息；Device 部分读取输入并计算。补偿求和用于降低长点积的舍入误差；行最大值从负无穷开始；输出后刷新数据缓存。

CPU 检查执行的是从实际源文件生成的验证副本，只替换芯片专用标记、张量访问接口和启动语法。它能检查计算与索引，无法验证 Ascend C 编译、缓存行为或 NPU 性能。提交文件中没有 CPU 计算分支。

本次 CPU 检查最大绝对误差为 `0.000244140625`，所有 96 组均满足模板使用的组合判定 `abs(error) <= 1e-4 + 1e-4*abs(golden)`。该结果不构成对未公开测试数据的精度保证。

技术依据：[Ascend C 核函数修饰符](https://asc.gitcode.com/guide/programming_guide/language_extension/simd_builtin_keywords.html)、[CANN 9.0 缓存刷新接口](https://www.hiascend.com/doc_center/source/en/CANNCommunityEdition/900/API/ascendcopapi/atlasascendc_api_07_0177.html)。赛事要求见上合赛区官方公告及正式规则，来源汇总在根目录参赛梳理文档。
