# 第 12 步：官方大点的形状定位与四个被否定的假设

核对日期：2026-10-16。提交截止 10 月 17 日 18:00。晋级线实测：第 32 名 60.73，第 33 名 60.34，共 646 队。

## 一、指纹法：怎么确定官方测试点的形状族

官网 V36→V54 在点 8–12 的耗时比值是 **1.011 / 0.967 / 1.006 / 0.987 / 1.011**，即十几项改动后纹丝不动。因此**只有本地 V54/V36 比值也 ≈1.0 的形状才可能是它们**。

| 形状族 | 本地 V54/V36 | 结论 |
|---|---:|---|
| 瘦长大 K（M 或 N 小、K 大） | 1.012–1.037 | 候选 |
| 大矩阵短 K（4096²×32 等） | 0.586–0.662 | **排除** |

进一步用绝对耗时匹配，锁定到 **B=64 + M/N 都很小 + K=8192** 这一族：

| 本地形状（V54） | 耗时 | 官方点 |
|---|---:|---|
| `64×8×128×8192` | 134.18 μs | 点 10 = 134.99 |
| `64×16×16×8192` | 373.12 μs | 点 11 = 412.64 |
| `64×16×64×8192` | 88.28 μs | — |

**这解释了之前所有的「本地大幅提升、官网纹丝不动」**：V43 的折叠列归约、V54 的双缓冲提速的是「大矩阵短 K」族，而官方大点在另一族里，两者不相交。

## 二、这族形状的流水分解

对 `2×17×1024×8192`（同族，PipeUtilization）：

| AIC（72.16 μs） | 时间 | 占比 | | AIV（73.36 μs） | 时间 | 占比 |
|---|---:|---:|---|---|---:|---:|
| mte2 搬入 | 44.47 | **58.5%** | | **vec 归约** | **0.53** | **0.7%** |
| 等 mte1 阻塞 | 33.08 | — | | mte2 | 0.26 | 0.3% |
| scalar | 15.82 | 20.8% | | | | |
| **cube 实算** | **3.04** | **4.0%** | | | | |

**AIV 几乎完全空闲**。所有归约侧优化在这族形状上都是空转。

`64×16×16×8192` 的物理账：输入 33.6 MB，按 800 GB/s 访存下限 **42 μs**，实测 **373 μs（差 8.9 倍）**；TBest 65.53 μs ≈ 513 GB/s，正是访存受限水平。

## 三、本轮被实测否定的假设

| 假设 | 实验 | 结果 |
|---|---|---|
| **baseK 太小导致 A 跨步读低效** | 环境变量扫 baseK ∈ {自动,512,1024,2048,4096,8192} | **否定**。`64×16×16×8192` 在所有取值下持平 370–374 μs（波动 <1%）；另两个形状随 baseK 增大单调恶化（`64×8×128×8192`：132.76→568.86）。自动选择已最优 |
| **省掉打包缓冲的 memset** | V60 | **有害**。跳过转置缓冲清零后，M 非 16 倍数时填充行留脏数据 |
| **不打包 B** | V59 | **更差 19–21%**。packB 是两害相权的较优解 |
| **L1 深度在 A/B 间对调** | V56 | **更差** |
| **窄 N 路径提到 Cube 之前** | V38 | **有害**，174→271 μs |

baseK 扫描的附带价值：这族形状**对 baseK 也免疫**，说明时间既不在 AIV 归约、也不在 Matmul 的 K 循环里。B=64 意味着 **64 个独立 Matmul 会话**，每核摊 3 个、每个 124 μs 却只读 512 KB、算 200 万次乘加 —— 剩余嫌疑是**每会话固定开销 × 64**，对应的方向是批量 Matmul（`SetBatchNum`/`IterateBatch`），而非调分块参数。

## 四、本轮唯一的真实收益：A 的 K 维连续化

`ta=1` 时 A 存成 `[K,M]`，K 是归约维，M 小则每行只有十几个元素连续，K 大则碎片访存重复几千次。四种转置组合在 `2×17×1024×8192` 上：

| 组合 | A 的 K 维 | B 的 K 维 | 耗时 |
|---|---|---|---:|
| t01 | 连续 | 连续 | 49.60 |
| t00 | 连续 | 跨步 | 77.16 |
| t11 | 跨步 | 连续 | 169.38 |
| t10 | 跨步 | 跨步 | 248.92 |

代价与 M、K 强相关：M=17/K=8192 慢 3.2 倍，M=1024 或 K≤2048 则无代价。

**修法（V57→V63）**：`ta=1` 且 M 小 K 大时，在设备上把 A 转置成 `[M,K]`，再以 `ta=0` 跑 Matmul。实测 `1×16×8192×4096 t11` 3.85 倍、`2×17×1024×8192 t10` 3.15 倍。门槛 `ta && K>=2048 && M<=256 && B*M*K<=2^21`，属一般形状条件。

### 两次踩坑

1. **假提速**：首版因外层 `if(paddedA||paddedB)` 不含 `flippedA`，转置段从未执行，矩阵乘读了一块被 memset 清零的缓冲 —— 又快又错。是 pipeline 套件里 BF16+ta=1+K=8192 那个用例抓出来的。**速度验证必须配正确性验证**。
2. **连带回归**：V57 建在 V55 之上，而 V55 把 `SetFixSplit` 的 baseK 全局钉成 512，让点 15 从 30.34 恶化到 139.66 μs（+360%），吃掉全部收益。V63 已撤回自动。

## 六、到 60 分还差什么

计分 `100/(1+log₁.₅(t/T))` 要求 15 个点**全部**在最优的 1.3 倍以内。当前各点是 2–7 倍。今天验证过的所有结构级想法都已被实测否决（服务模式慢 3 倍、不打包慢 20%、双缓冲深度 2 慢 56%、两种选块规则都更差、L1 对调更差、baseK 无效）。

唯一未尝试且有数量级空间的方向是**批量 Matmul**：把 B=64 的 64 个独立会话合成少数几次，针对的正是官方大点族。但这是对 `bmmms_cube_kernel` 的结构性改写，不是参数调整。
